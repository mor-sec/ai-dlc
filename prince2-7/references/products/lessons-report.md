# Lessons report

**Purpose:** passes on lessons that can be applied to this project or to other projects. It can be produced at any time (for example at a stage end) and must be produced at closure.

| | |
|---|---|
| **Created in** | SB (optional) and CP (always) |
| **Prepared by** | Project manager |
| **Received by** | Project board, which decides who in the organisation should receive it |
| **Derived from** | Lessons log, quality register, issue register, risk register, end stage reports |

## Composition
1. **Executive summary**
2. **Scope of the report**: the stage or the whole project
3. **Review of what went well and badly**:
   - project management method (including tailoring)
   - specialist methods and tools
   - project strategies and approaches
   - project controls
   - abnormal events causing deviations
4. **Review of useful measurements**: estimating accuracy, effort, defects found and where, cost of quality, and AI usage metrics where relevant
5. **Significant lessons**: for each, give event, effect, cause or trigger, early warning indicators, and recommendation (from the lessons log)

## Quality criteria
- Lessons are specific and actionable, not general statements ("communication could be better").
- Each lesson has a recommendation and a proposed owner.
- Corporate lessons are separated from project-only lessons.
- Positive lessons are included, not only failures.

**AI notes:** for each lesson about agent use, recommend where it should land:
- the agent instruction files (CLAUDE.md, AGENTS.md, steering files);
- a reusable skill;
- the AI-DLC team knowledge or memory;
- an organisational standard (for example the digital and data management approach template).
