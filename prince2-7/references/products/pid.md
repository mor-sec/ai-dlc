# Project initiation documentation (PID)

**Purpose:** the project baseline. It defines the project and how it will be managed, and it is the basis for the board's decision to authorise the project. It is a collection of products, not necessarily one document.

| | |
|---|---|
| **Created in** | Initiating a project (IP) |
| **Updated** | In SB, when baselines change (re-baselined versions are kept, not overwritten) |
| **Prepared by** | Project manager |
| **Approved by** | Project board, in DP (authorise the project) |
| **Derived from** | Project brief, discussions with the board, organisational standards, lessons |

## Composition

1. **Project definition**: refined from the brief. Background, objectives and desired outcomes, scope and exclusions, constraints and assumptions, project tolerances, users and interested parties, interfaces.
2. **Project approach**: delivery approach and the reasons for it.
3. **Business case**: full version (see `business-case.md`).
4. **Project management team structure and role descriptions**: named people, assurance arrangements, change authority and change budget.
5. **Management approaches**: benefits, change, commercial, communication, digital and data, issue, quality, risk, sustainability. See `management-approaches.md`. Each may be short or may reference an organisational standard.
6. **Project plan**: see `plan.md`. Include the management stage boundaries.
7. **Project controls**: stage boundaries and why they fall there, tolerances delegated to stage and work package levels, reporting cadence, escalation routes.
8. **Tailoring**: what is tailored and why (see `tailoring.md`).

## Quality criteria

- It is consistent with the brief, or differences are explained.
- The business case, project plan and risk register agree on cost, time and major risks.
- Every role has a named person, and the three interests are all represented on the board.
- Tolerances exist at the project level and are delegated to the stage level.
- Stage boundaries align with key decision points, not arbitrary dates.
- Approaches are proportionate; "use org standard X" is acceptable.
- It says how the PID will be kept current and versioned.

**Ends with:** decision required. Authorise the project and the next stage, with the stage plan for that stage attached.

**AI notes:**

- State agent use in the project approach and the roles section: who supervises which agents, and which decisions are reserved to humans.
- The digital and data management approach must cover AI tooling (see `ai-sdlc.md`).
- If using AWS AI-DLC, record which workflow profile and gates apply per stage under tailoring.
